Members issue [personal access tokens](/integrations/personal-access-tokens) to let tools such as the [MCP server](/integrations/mcp-server) call OpenInspect as them, either in Settings or by signing an MCP client in with OAuth, which issues the client a token. **Settings › API policy** lets you set the rules every token follows, turn the hosted MCP server and OAuth sign-in off, choose which apps can sign in, and revoke any member's tokens.

You need the **Manage personal access tokens** permission (`workspace.personal_access_tokens.manage`). Owners and Administrators have it; you can add it to a custom role, for example a security reviewer's, without granting member management.

## The policy

The policy applies to existing tokens the moment you save it, not only to new ones:

| Setting                          | Effect                                                                                                                                                                                                                                                                                                                           |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Allow personal access tokens** | Off refuses every token at once and stops members creating new ones. Tokens are not revoked: turning it back on restores them.                                                                                                                                                                                                   |
| **Allow MCP clients**            | Off answers the MCP server at `/mcp` as though it did not exist, turns OAuth sign-in off, and refuses every token an app received by signing in, everywhere. Tokens members made in Settings keep working with the API directly. The setting shows the server's URL to give members.                                             |
| **Apps that can sign in**        | The MCP clients members can sign in with OAuth, each named by the URL of its client ID metadata document. **Claude (default)** allows claude.ai, Claude Desktop and mobile, and Claude Code. OpenInspect fetches only the documents listed here, and only from public hostnames. Removing an app stops the tokens it was issued. |
| **Longest lifetime**             | Tokens older than this stop working, even if they were issued for longer. New tokens cannot be issued for longer.                                                                                                                                                                                                                |
| **Permissions tokens may hold**  | Narrows every token's grant to these permissions, and new tokens cannot be granted others. Workspace administration permissions are never available. Allowing **Manage skills** also allows **Read skills**, which a token needs to use it.                                                                                      |

A token an app receives by signing in is an ordinary token: the lifetime cap and permission ceiling apply to it, the member chooses its permissions and lifetime when they allow the app, and it is listed and revoked like any other. Apps sign in with a client ID metadata document only; there is no dynamic client registration, and no refresh token, so an app signs in again when its token expires.

### Sign-in needs reachable URLs

OAuth sign-in uses both public URLs: the web app's origin is the issuer, which serves `/.well-known/oauth-authorization-server`, the consent page at `/oauth/authorize`, and the token endpoint at `/oauth/token`, and the control plane serves the MCP server and its `/.well-known/oauth-protected-resource/mcp`. Sign-in is unavailable unless the control plane knows both (`WEB_APP_URL` and `WORKER_URL`).

Hosted Claude apps fetch these from Anthropic's servers, not the member's browser. Anything in front of the web app that challenges unauthenticated requests, such as Vercel deployment protection or Cloudflare Access, breaks sign-in; leave the metadata and token paths reachable, and allow Anthropic's outbound addresses through any firewall. Anthropic publishes them on its [IP addresses page](https://platform.claude.com/docs/en/api/ip-addresses) and says they will not change without notice; when this page was written they were the IPv4 ranges `160.79.104.0/21` and `153.61.208.0/20`.

Turning tokens off is the fastest response to a suspected leak when you do not know which token leaked. Every policy change is recorded in the [audit log](/administration/audit-log) with the settings before and after, and saving refuses to overwrite a change someone else made since you loaded the page.

## Members' tokens

The same page lists every member's tokens, newest first, with each token's owner, permissions, last use, and expiry. It never shows a token's value; OpenInspect stores only a hash.

- **Revoke** stops one token immediately.
- **Revoke all of a member's tokens** stops every token that member holds, for example when a laptop is lost. It checks again until no token is left, so tokens created while it runs are revoked too, but one created after its last check is not. If someone may still be creating tokens as the member, suspend the member first.

Revocations are recorded in the audit log with you as the actor and the member as the target. A member's tokens are also refused while the member is suspended, and deleted with the member's account.
